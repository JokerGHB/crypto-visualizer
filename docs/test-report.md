## 1. 测试概述

### 1.1 测试目标

1. 验证 AES 实现与 FIPS-197 标准完全一致（这是整个平台可信的前提）。
2. 验证 `Trace` 数据契约的不变量，保证前端可视化不出现状态错位。
3. 验证接口的鉴权、校验、越权与限流行为符合安全设计要求。
4. 验证 AI 服务不可用时的降级路径完整。
5. 验证前端播放状态机在各种边界操作下不失控。
6. 在真实浏览器中验证端到端功能可用。

### 4.2 测试中发现并修复的缺陷

端到端测试的价值在于它抓到了单元测试覆盖不到的真实问题：

| 编号 | 缺陷 | 原因 | 修复 |
|---|---|---|---|
| D-01 | 解密页签切换后结果错误 | 解密模式下输入框仍填明文，用户无法得知应填密文 | 输入框标签随模式显示「明文/密文」，并加占位提示 |
| D-02 | 加密→解密需手工复制密文 | 缺少联动 | 切换模式时自动把上一次输出填入输入框 |
| D-03 | 历史记录页显示 0 条 | `onMounted` 时登录态尚未恢复，`load()` 提前返回 | 改为 `watch(isLoggedIn, immediate)`，登录态就绪后加载 |
| D-04 | 练习页首屏空白 | 同 D-03 的登录态时序问题 | 同上 |
| D-05 | 密钥扩展卡把页面撑到 2706px | 11 张卡片全部展开纵向堆叠 | 改为可折叠，默认只展开当前播放轮 |
| D-06 | 轮密钥字溢出卡片边界 | 4 个字 × 4 字节横向排列超出侧栏宽度 | 允许换行、缩小字号与内边距 |
| D-07 | 时间轴轮次被裁切 | 容器 `overflow: hidden` | 改为仅密钥扩展卡片裁剪，时间轴保留滚动 |

修复后页面高度从 2706px 降至 1201px，25 项全部通过。

## 5. 安全测试

| 测试项 | 方法 | 结果 |
|---|---|---|
| XSS | 用户名输入 `<script>alert(1)</script>` | 被 Pydantic 正则拒绝（422） |
| XSS | AI 返回内容含 HTML 标签 | 前端使用文本插值，标签被转义显示 |
| CSRF | 从其他源发起带 Cookie 的请求 | 令牌不存 Cookie，请求无鉴权，返回 401 |
| 越权 | 用 A 用户令牌访问 B 用户记录 | 返回 404（不泄露资源存在性） |
| 输入校验 | 提交 `zz` 作为 hex | 返回 422 |
| 输入校验 | 提交 31 位密文 | 返回 422 |
| 口令长度 | 注册 73 字节口令 | 明确拒绝并提示，不静默截断 |
| 限流 | 1 分钟内第 21 次 AI 请求 | 返回 429 |
| 安全响应头 | 检查任意响应 | `CSP`、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff` 均存在 |
| 敏感信息 | 检查用户接口响应 | 不返回 `password_hash` |
| 密钥泄露 | 检查仓库 | `.env` 已在 `.gitignore`，仅提交 `.env.example` |

## 9. 测试结论

139 项测试全部通过，覆盖算法正确性、契约一致性、接口安全、降级路径、前端状态机与真实浏览器端到端功能。

算法实现与 FIPS-197 标准完全一致（4 条标准向量逐位相符），这是平台可信的基础。安全测试中越权返回 404、令牌走 Authorization 头、口令显式拒绝超长等设计经过验证有效。

端到端测试发现并修复了 7 个真实缺陷，其中 3 个是单元测试无法发现的登录态时序问题，说明真实浏览器验证不可省略。

遗留问题均为已知限制，不影响本期验收标准，已在设计文档中记录改进方向。
